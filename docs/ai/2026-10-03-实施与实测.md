## Docker 恢复

截图中的故障发生在 Docker Desktop 4.65.0 的 Windows `dockerInference` 通信端点初始化。原本 `C:\Users\LOVER\AppData\Local\Docker` 是指向 `E:\docker` 的目录链接。反复重启仍失败，而独立目录的 Unix socket 探测成功。

进一步验证发现，AppData 下新建运行目录也不稳定：Docker 的 Volume Backup Scheduler 在同目录改名时收到 Windows 错误17（不能跨盘移动），随即停止管理服务。此时 Linux 引擎虽在运行，Windows Docker API 已不可用。用独立小文件复现了该目录的改名失败；`C:\Users\LOVER\DockerLocalRuntime` 下同样操作成功。这是已确认的文件系统行为差异，尚不能据此确定 Windows 底层成因。

自动审批拒绝了移除旧目录链接并重建真实目录的操作，返回 `blocked by policy`，未给出更具体原因；没有执行该删除操作。之后使用不删除原目录的方案恢复：

- Docker 进程单独使用 `LOCALAPPDATA=C:\Users\LOVER\DockerLocalRuntime`。没有改变用户/系统全局环境变量，未更改 Windows 加密或安全设置。
- 运行目录的`Docker\wsl` 仍链接 `E:\docker\wsl`，原 6.4GB 数据盘没有搬动或重建；tasks 目录也复用原位置。
- Docker 启动后能看到原有容器；启动原 `podcast-mongodb`，MongoDB `ping` 返回 `1`。又正常退出 Docker，使用 Windows PowerShell 5.1 执行修复脚本重新启动，命令行与原容器均再次恢复。
- 桌面新增 `Docker Desktop - 本地运行目录.lnk`，调用 `backend/scripts/start_docker_local_runtime.ps1`。以后完整退出 Docker 后用这个入口启动；原快捷方式仍可能走故障路径。

早期诊断时，旧运行目录分别改名保留在 `E:\docker\run.before-repair-20261003-010051` 和 `E:\docker\run.before-local-socket-repair`。`E:\docker\run` 当前指向 `C:\Users\LOVER\AppData\Local\DockerRuntime`；AppData 下的 `PodMasterDocker` 也是早期试验目录。这些路径均不是最终运行目录，保留用于回查，没有删除备份或容器数据。

## 已接入产品的逻辑

1. 初筛只读取标题、节目名、简介。入选只需id和decision，原因与话题列表可省略；排除/不确定时提示模型简要说明。原因保留给材料界面，不再反复进入汇总。
2. 每篇完整原文一次分析：导读、分议题摘要、精选原话、概念方法、实际资料。全文加稳定P编号，未截断，编号不产生额外调用。
3. 普通议题、概念、资料返回原文段落ID；后台存储真实原文、偏移、字幕时间和全部支持段落。单篇页面与周期报告都能展开这些段落。
4. 取消12议题及摘要字段的硬长度门槛。精选原话独立做连续原文定位；唯一可确认的逗号/空白差异回填原文，改词、缺词、数字旁标点或歧义仍不接受。
5. 个别错误局部保留审计并略过，不重写整篇。结构完全不可读或所有议题均无效时明确失败；单篇/新汇总每次只调用一次，不做整份校验重试。
6. 五栏目汇总一次调用。核心与联系生成短文；原话/概念/资料返回候选ID，后台继承原记录。只请求一个栏目时仍按需生成。旧Sxx研究档案保留旧分块流程。
7. 汇总不发送普通观点的完整英文段落和重复译文；系统公共规则与排序稳定的材料在前，关注问题和本次任务在后。
8. 记录供应商返回的cached_tokens、cache_miss_tokens、reasoning_tokens、provider、finish_reason、可见输出字符数和调用次数。未知明细不伪装成0。一次汇总产生的五份报告共享generation_id，用量仅分配到第一份，避免累计五次。

单篇缓存由正文、分析版本、提示词、模型配置确定，与周/月或关注话题无关。本次升级为v2，旧v1缓存不会伪装为v2；现有成品报告和收藏保留，生成新版时才更新单篇分析。没有后台批量重跑九月内容。

同一份生产分析记录按旧格式准备汇总材料为28,493字符，当前精简格式为9,072字符，减少68.2%。这只衡量材料体积，不冒充模型token或已经验证的汇总质量收益。

关闭思考的原话逐字匹配下降，且两种调用返回的缓存/思考明细不完全一致，供应商均未提供可辨认的实际路由（provider为`-`）。因此这一轮保留默认思考，不根据一次快响应推断所有节目同样可靠；额度恢复后的轻量思考验证见本文顶部的续跑更新。生产样例中思考9,137 token，仍占输出很大部分，值得后续独立评估。

# 播客知识工作台：五种分析实验

日期：2026-10-01（Asia/Hong_Kong）。本文件是实验产品方案，尚未表示各项能力已经上线。实际样本、模型运行结果和验证记录由实验快照给出。

## 产品目的

依据 [中文 README](../README_CN.md)、[架构](./architecture.md)、[AI 功能](./ai-features.md) 和 [ADR-004](./decisions/004-task-queue-threadpool.md)，已有产品是本地优先的播客与视频订阅工作台：把 RSS、YouTube、B站内容汇入共享库；优先自动取得字幕，没有字幕时由人决定是否本地转写；摘要和分析使用管理员维护的一套模型配置；已读、收藏和收听进度属于个人。

下一步的价值是把已取得的完整内容变成用户能继续使用的知识：知道先看什么，围绕问题理解原因，比较不同主张，形成可验证的下一步，并在需要时核查公开原始资料。订阅管理和播放器提供内容的取得与回看；AI 工作台负责跨内容组织与回答，结论始终能回到原文。

## 本轮可比较的输入

所有模式使用同一份最近十条可用完整内容快照，并固定 source ID、单集 ID、标题、发布时间、内容来源、全文、原文定位及内容指纹。这里的“最近十条可用完整内容”不自动等于“全库最新十条单集”：尚无完整文稿的新集必须在排除清单中可见，不能以标题替代后仍标作全文阅读。

先明确全文是平台字幕、外部文稿还是本地转写；“读取了全部现存文稿”并不保证文稿与音频逐字完整或无误。五模式不得偷偷改变样本、复用旧雷达报告或只读取头尾。主题 focus 的输出可以集中于相关来源，但必须说明其余来源对这个问题不相关，而不是从输入中隐去。

本轮将互联网材料独立存为 W01 等来源，本地内容为 S01 等来源。互联网材料只在 research 中参与核验和补充；其他模式若使用，应显式标注，不可把网页观点归给播客嘉宾。

正式冻结快照包含十条文稿，共 281,782 字符，内容发布时间按香港本地时间为 2026-09-26 至 2026-09-29（UTC原始记录始于09-25）。S01 是 Cory Doctorow on AI, Work, and Power（61,346 字符），S02 是 Claude Code 访谈（102,473 字符），S10 是 OpenRouter/token 经济访谈（84,066 字符），S08 为 TCL 对谈（25,019 字符）。另有四条不足 80 秒的短片，以及两条约八分钟的视频；均使用完整现存文稿。短片不是被截断的长访谈，也不能被当作与长访谈同等丰富的证据。其余来源包含 AI 评测和对齐讨论、战争目标、罗素与生物科普；focus 应如实说明哪些支持“Agent 开发与产品落地”，哪些仅能提供标明为编辑推断的类比，哪些不相关。来源编号在冻结前曾调整，网页关系记录使用标题，页面依据冻结快照建立最终编号。

## 五个业务任务与成果

| 策略 | 最适合谁 | 用户要完成的事 | 核心成果 | 与其他模式的差异及风险 |
| --- | --- | --- | --- | --- |
| daily · 本期精选 | 忙碌订阅者，先决定投入注意力的位置 | 在有限注意力下决定先看／听什么 | 少量有依据的重点、值得先看的单集及具体理由、清楚的输入覆盖 | 优先排序和导航；风险是用不透明重要性代替用户兴趣 |
| focus · 主题深读 | 带着问题学习的开发者、产品经理和研究者 | 围绕一个明确问题理解机制和适用边界 | 问题、跨集解释链、关键概念关系、原文证据、未回答的问题 | 深挖一个问题；风险是强行串起无关来源或把推断当原观点 |
| debate · 观点对照 | 面临技术／产品取舍，需要判断论证的人 | 弄清不同来源的主张是否真有分歧 | 同一问题的立场／依据／假设矩阵、共识、真正的分歧与可判别证据 | 比较论证而非语气；风险是为呈现正反方而编造对立 |
| actions · 实践清单 | 想把学习用到小项目和团队流程的实践者 | 把内容转成可以小步验证的候选行动 | 适用角色、候选实验、依据、步骤、成功指标、停止条件、投入和前置条件 | 产出可检验的行动；风险是缺少用户情境却给出过度确定的建议 |
| research · 联网核验 | 需要核对时效、技术细节和一手依据的人 | 判断播客里的说法哪些可确认、哪些需补充 | 待核验主张、本地证据、一手网页、支持／修正／无法核实的结果、日期与剩余问题 | 比较外部事实与本地内容；风险是把搜索相关性当核验，或混淆材料年代 |

### daily：选择而非新闻榜

输入窗口没有前期基线，因此不生成涨跌百分比；展示本期来源数和提及集数。排序理由围绕材料解释充分度、跨来源关联、具体性与用户明确任务，避免不透明的“重要性 97 分”。默认给出可读的排序解释，例如“这一集提供完整方法，另一集提供实践边界”。提供打开单集、查看证据和进入主题深读的入口。

### focus：一个可以回答的问题

问题可由用户输入，也可从完整内容中建议。结构为：一句话答复 → 机制／前提 → 至少两条不同来源的证据（若材料确实支持）→ 何时不成立 → 需要追问的内容。材料不足时允许“这十条没有回答”；不强求每个来源都参加每个主题。

### debate：差异必须落在可比较的命题上

对照共同的判断标准和适用情境，不把讨论不同问题的两个人排成正反方。输出“支持同一结论但假设不同”“实践取舍不同”“真正矛盾”“证据不足”这些关系。不能代嘉宾写新观点；编辑推演必须标为本轮分析。名字和说话人只在原文能可靠确认时展示。

### actions：候选实验而非代作决定

每条行动写清“谁在什么情境下可以尝试、为什么、最小步骤、如何检查结果、何时停止”。例如以固定样本比较上下文组织方式，需要同模型、同问题、人工核查引用准确度；不能从某研究泛化为“立刻弃用长上下文”。建议、原文主张和用户已采纳的任务是三种不同状态，页面不把建议当承诺。

### research：带日期的公开补充

每个待核验主张保留 S 来源。当前实时检索接口在用户开启补充后，只把填写的研究问题发送给搜索服务，不发送订阅全文；页面说明这一行为。未配置搜索服务时使用本次保存的网页摘读笔记，此路径不会发起新搜索。后续可增加公开关键词预览，便于处理包含个人背景的问题。本次资料优先论文／作者研究页、公司官方公告与官方文档。保存真实 URL、发布日期、访问日期、阅读范围和关系；无日期就留空。网页内容写成 W 来源的摘读笔记，不伪装整页全文或逐字原文。

网页证据可支持、补充或修正一个主张，也可能无法核实。当前文档说明的功能不能回填成历史播客发布当时已存在的功能。特别区分 Claude 插件打包、多代理会话团队和多个人共同使用代理这三个概念。

已访问的一手补充材料登记于 `backend/.runtime/briefing-lab/web-context.json`：W02/W03 对应 Claude Code 访谈的插件背景，W04/W05 区分该访谈中多人协作与多代理机制，W06 提供上下文维护的工程背景，W07 提供 TypeSafe 评测短视频的工作流评估对照，W08 补充 OpenRouter 访谈的供应商路由，W09 核验罗素短视频涉及的 1955 年宣言。W01 Chroma 研究仅作实验方法背景，因为本次十源中没有 Chroma/Context Rot 直接讨论。OpenRouter 访谈的未来市场规模是嘉宾预测，不能由路由文档核验成当前事实。本轮离线登记的网页材料属于 `saved_primary_source_notes`，不是运行时实时搜索 API，也不是网页全文。

## 默认入口及页面结构

本轮实验默认打开 daily 阅读编辑部，focus 的初始问题为“Agent 开发与产品落地”。用户可以直接进入问题模式，也能查看同一十源上的另外四种业务任务。实验页保留五模式，便于用实际内容比较哪种最有用；最终产品方案由用户在查看结果后选择。个人提问生成的结果按用户隔离，本次公开实验样本共享；订阅材料和逐篇阅读记录仍属于共享库。

长期入口有两个可检验方向：偏订阅消费的用户先看 daily 的“值得关注什么、为什么、从哪一条开始”；偏知识工作的用户直接输入问题进入 focus。两种入口都可以继续对照观点、制定候选实验和联网核验。此处是产品建议，不表示已经替用户决定长期默认方案。

侧栏按“本期精选／我的问题／主题／实践／来源库”组织知识工作；来源库与传统订阅树都可抵达同一集。传统模式继续承担订阅源、发布时间、未读、播放进度和单集操作。AI 模式承担跨集问题与成果导航，并保持来源抽屉、单集原文和播放器可达。两者不是两套隔离资料库。

页面顶部显示固定样本、内容时间跨度、完整输入覆盖和分析生成时间；“生成时间”与“内容发布时间”分开。每条结论可展开原文依据，S 和 W 使用不同标识。更换问题或输入但尚未生成时，保留上次有效结果并显示尚未应用的设置；导出绑定已显示的结果。加载进度应说明在读取哪些源、生成哪个成果、验证哪些引用，而不是只有无限闪烁。

## 全文阅读、溯源与成本准则

本轮以质量和完整阅读为先，成本可接受，不设置为了省 token 而任意截取头尾的规则。十源能够安全放入配置模型的输入窗口时，五模式直接使用同一份完整内容进行独立分析，便于比较业务任务本身。记录每次模型名、输入／输出 token、实际调用次数和耗时；这不是费用数字，未知单价不估造费用。

超过模型窗口时，先将全文按段落切成覆盖全部内容的片段，每片段保存连续原文范围，完整逐片阅读后再做逐源整合。保留原文和引用位置，最终综合可以按问题重新读取相关原文。必须展示分片数与覆盖率，不能把 150 字压缩摘要说成已阅读全文。若既没有完整输入也没有完整分片覆盖，则标为部分阅读而非完成。

本轮实现采用完整连续分片取证，再由五任务共享逐段摘要、观点及逐字引文做综合。每一段都输入过模型、引文必须逐字匹配，综合阶段也能读到真实引文；但没有把十源全文再次输入五遍，也没有自动核查每个观点和引文之间的语义关系。因此页面应称“全文逐段分析后综合”，不能称“五个模型各自完整重读全部原文”。阅读阶段的 token 与综合阶段的 token 分开记录；实验总量需要相加，缓存复用则说明不重复计入本次新增调用。程序通过的引用还要抽查是否真正支持结论。

本轮逐条取证校对发现真实的数字错配与字幕歧义：例如把 Anthropic 的收入引文用于 OpenRouter 开发者人数，以及把未含 not 的十年规模句子翻译成相反语气。修正保留原 claim、原摘要、模型和 usage 记录，写明校对原因。研究版进一步检查九项成果，补对应证据或收窄无法由引文支持的断言，保留 `editor_review`；这是额外的原文核对步骤，不等于实现了自动语义判定器，也不保证所有音频字幕没有错词。

引用不仅需要 ID 存在，也要内容支持所述结论。程序校验来源 ID、关联单集 ID、逐字引述在原文中的匹配；引述与解释分开。没有可靠逐字原句时使用明确的转述，不加引号。时间点只可来源于实际字幕段或可验证定位。网页笔记仅支持其覆盖的摘读范围，不被标为网页全文。

统计字段由程序计算。模型只能建议标题、解释、关系与排序理由；不得自由生成真实单集标题、时长、次数或百分比后直接当作数据库事实。

Chroma 的 [Context Rot 原研究](https://www.trychroma.com/research/context-rot) 指出长输入可靠性并非均匀；Anthropic 的 [上下文工程文章](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) 讨论按任务组织信息。由此推断，本项目需要同时检查完整覆盖和原文支持，不能把“输入更多”本身当质量保证，也不能将“精简上下文”当跳过原文的理由。

## 本轮编排：先保留简单流程

固定流程为：固定输入快照 → 检查完整覆盖 → 五业务任务各自分析 → 验证引用和结构 → 保存成果快照 → 页面展示。research 在分析前取得外部材料并明确其身份。每阶段保存状态和已完成成果，失败只影响对应模式，页面可继续查看其他成果。并行度由现有模型服务容量与线程池配置决定。

建议复用现有 Flask、LLMClient、ThreadPoolExecutor 和任务状态能力；本轮不用新增 LangGraph 依赖或抽象策略框架。[Python 官方 ThreadPoolExecutor 文档](https://docs.python.org/3.13/library/concurrent.futures.html) 支持提交独立任务，并提醒同池任务互相等待可能死锁。[Flask 后台任务文档](https://flask.palletsprojects.com/en/stable/patterns/celery/) 的具体例子使用 Celery，但其长任务快速返回 ID、后台处理、轮询成果的设计原则也适用；它不是在为本项目的 ThreadPoolExecutor 提供直接保证。

[LangGraph 官方概览](https://docs.langchain.com/oss/python/langgraph/overview) 提供长运行有状态流程、持久化与人参与流程的底层能力。如果后续真实出现多轮“提出疑问 → 搜索 → 判断不足 → 继续搜索”、人工修正中断、跨进程恢复与动态分支，再评估 LangGraph。选择它也需要真实持久化配置；[持久化文档](https://docs.langchain.com/oss/python/langgraph/persistence) 说明内存 checkpointer 在进程重启后会丢失。框架不能替代输入完整性、引用核验或业务任务定义。

## 取得内容的运行问题

本轮实测记录显示 Clash 的 7891 代理端口能够访问 YouTube，7890 出现 SSL EOF，直连超时；这说明网络路径是一个独立变量，不能把所有获取失败归给 AI。自动刷新原先不识别视频源类型，错误地把频道 URL 交给 RSS 解析器，并且失败源不会再被自动选中；修复方向是复用手动 YouTube/B站刷新流程，失败后也按六小时检查间隔重试。B站当前凭据被平台判为登录无效，需要用户处理有效会话；重试流程本身不能恢复凭据。实验未修改用户的代理或 SESSDATA，也不以批量刷新掩盖这些诊断。

## 评估与完成条件

| 维度 | 如何观察 | 本轮最低要求 |
| --- | --- | --- |
| 输入完整性 | 每源全文长度、覆盖范围、未纳入清单 | 固定十源，完整输入或完整分片覆盖；来源清楚 |
| 引用支持 | 逐条检查结论和引述是否由所标来源支持 | 来源 ID 全部真实；引述必须匹配原文；无凭空百分比 |
| 五任务差异 | 隐去模式名后能否从成果识别任务 | 选择、解释、对照、行动、核验各有独立成果 |
| 跨来源价值 | 是否提出单集摘要没有的联系与适用边界 | 支持确实存在的关系，不强行关联十源 |
| 用户可行动性 | 是否能据此打开来源、深入问题或尝试验证 | 核心成果有明确下一步；没有泛泛口号 |
| 诚实边界 | 事实／转述／推断／建议／外部补充是否可辨 | 来源不足时允许不下结论；不存在的观点不补写 |
| 时效性 | 发布时间、访问时间、生成时间与内容指纹 | 历史材料不冒充当天新闻；当前资料不冒充历史状态 |
| 实际成本与稳定性 | 调用／token／耗时、单模式失败、重复读取 | 展示真实测量；缓存绑定内容指纹与问题；可局部重试 |

只有真实结果完成、引用检查通过且网页能够查看同一份十源与五份成果，才称作本轮实验完成。设计文档和漂亮的空页面本身不能证明五种分析有价值。

# AI 简报：先定内容块与报告版式

2026-10-01 的方案记录。最新页面将五种内容模式与视觉风格分开，并保留按需展开的单篇解读，实际取材、PDF 和限制见 [实现记录](./briefing-reports.md)。下文保留此前按五种内容角度编排时的方案与预算；它不再代表当前界面。此前替换导航、默认提问和长篇问答的方向不再作为设计依据。

## 固定产品边界

产品仍是用户已有的播客订阅与收听工作台。简报帮助用户快速看到所关注节目里的新词、原话、资料和背景，随后回到对应节目收听，或把精选内容导出成一至两页报告。

左侧与左上角完整保留：原 PodMaster 标识、256px 侧栏、传统／AI 简报切换、所有节目、我的喜欢、工作台、订阅列表、底部设置与添加播客。保留原语言切换。五种方案的选择和关注项放在右侧主内容区，不另建品牌、独立侧栏或编号导航。

右侧设置可写为：`范围：最近十篇有文稿的节目｜关注：新词、金句、文章｜主题：可选｜报告：一页／两页`。主题可以是 AI 编程、商业、历史等关键词，用户不用先组织成提问。未填写主题时按所选节目整理，不能默认把其他订阅挤出报告。

## 原有逻辑应继续使用

单集摘要模板已经有 `key_concepts`、`key_quotes`、`resources` 和 `guest_background`，详情页也已有相应内容块。旧简报已有 `newConcepts`、`hotTopics.keyQuotes`、`relatedEpisodes` 和 `recommended`。应补全来源、定位和资源信息，再按报告版式编排。

上轮实验可以复用全文分段、引文匹配、正文抽屉和真实字幕时间；现有观点缓存不等于已经完成了专门的概念、金句、资料抽取。不能把观点换个标题直接当成新词卡。

## 五种方案

### 本期速览：综合一页简报，推荐默认

内容：本期术语、值得摘录的原话、节目提到的资料、重点节目。网页按块分区，纸面按两列安排。

一页初始预算：三个术语块、三个原话块、两个资料块，页尾列出涉及节目和完整材料入口。没有合适资料就减少块数；八块是版式上限示例，不是强制凑满。两页版本把嘉宾背景、额外资料和十篇来源索引放到第二页。

用户一眼看到本期有哪些值得留意的东西，每条直接标节目和时间。取舍：能快速浏览，但精选必然不包括每一集的所有观点；网页可展开完整候选，报告注明精选覆盖。

### 逐期摘录：按节目组织，适合不想混淆来源的人

每期使用一张节目卡：小封面、节目名、单集标题、嘉宾；一句话说明谈了什么；一个术语、一句原话和一条提及资料，缺项省略。底部保留收听和原文入口。

PDF 两页可先尝试每页五张紧凑节目卡，每卡只留约一百字正文；排版实测放不下时减少精选节目，并保留全部十篇的简短索引，不能缩成难读的小字。一页只选三至四期。

价值：最直接回答“哪一期说了什么”。取舍：同一概念可能在多期重复，跨节目关系需要额外点击查看。

### 本期新词：以概念解释为主，适合学习与积累

每块包含原词／中文名、约四十五至六十五字白话解释、该词在这期节目里的具体含义、原话证据、节目与时间。相同词可合并，但不同节目的用法分别显示。网页可附“还有哪期提到”，PDF 精选六至八个概念。

嘉宾、论文或历史背景只在确实帮助理解该词时补充，不写百科长文。未建立用户已知词或历史对比时，用“本期术语”而非宣称“你第一次听到”或“最近突然爆火”。

价值：回答“这个词是什么意思、他们为什么在这里说它”。取舍：需要解释原句，不能只罗列英文名与泛定义。

### 金句摘录：以原话与上下文为主，适合收藏分享

每块包含一段原话、说话人、节目、真实时间，以及一句交代当时在谈什么的上下文。英文可显示中文译文并明确标注，原文可展开。选择有具体判断或表达力度的句子，不能替嘉宾润色出新金句。

PDF 一页约六句短摘录；两页可增加上下文与少量嘉宾背景。网页可以选中、复制、收藏候选句，并从对应节目回听；最终功能仍需实现与测试。

价值：内容来自嘉宾的表达，减少 AI 的叙述占比。取舍：一句话很容易脱离语境，必须保留上下文，不把主持人提问、讽刺和假设写成嘉宾的定论。

### 提到的资料：以文章、书、论文、工具和网站为主

每块包含资料名、作者／机构、类型、哪期由谁提到、一句说明当时为什么谈它、原文证据和验证过的链接。直接标明关系：节目提到、嘉宾明确推荐、补充阅读。

PDF 一页约四至六条精选资料；两页可增加两位嘉宾的短背景及来源索引。搜索补出的相关资料不能混进“嘉宾推荐”，未找到确定原站时展示待确认书名或文章名，不造 URL。

价值：把听节目时来不及记的资料整理成可继续阅读的入口。取舍：实际节目可能没有提到文章；可以显示书或工具，也可以少出几块，不能为满足版式虚构。

## 用现有材料说明块应该长什么样

以下来自已保存文稿，示意报告内容，不表示新的提取流程已经生成完整五套报告。

**术语块：反向半人马（Reverse centaur）**

解释：机器安排工作节奏，人负责替它检查、收拾错误并承担后果。Cory 用这个比喻说明，AI 帮助人和人被迫服务 AI 是不同的工作安排。

来源：Software Engineering Daily · Cory Doctorow on AI, Work, and Power · Cory Doctorow。文稿定位在 07:51–12:07 的完整发言段，只有段落级精度，不能假称精确到一句话。

**原话块：李东生回顾一次并购判断**

字幕原话：“我就选择性的把一些风险因素给忽略了啊”

上下文：回顾收购汤姆逊时，他说成为全球化企业的目标近在眼前，影响了自己对风险的判断。

来源：钦文和他的朋友们 · 你看到风险，我看到未来。TCL45周年深度复盘｜钦文对话李东生 · 41:35 字幕段。按钮目标为“从这里听”“打开节目”“查看原文”。

**资料块：The Reverse Centaur's Guide to Life After AI**

关系：SED 本期介绍中提到的书名。先保存提及证据，再按完整标题和作者搜索出版社／作者原站，找到后补简介和链接；本轮不将未查询的新网页标为已经核实。

## 来源与收听必须直接可见

所有块都直接显示节目名称、单集标题、说话人（能确认才显示）和时间（真实存在才显示）。内部 S01／C002／E06 不作为用户的主要来源名称。

“打开节目”携带 episode_id 回到传统详情并选中对应节目。“从这里听”携带 episode_id 与字幕时间，先取得完整单集、切换播放源，再等待音频可定位时开始播放。当前程序只有打开对应节目和当前音频 seek，跨节目定位仍需补接线，不能称已经支持。

RSS／已有本地音频可复用播放器；YouTube 可尝试现有在线流，也提供带时间的原平台链接；B站等无法在应用播放的源提供原平台入口并显示时间。无时间的文章提供“打开原文”。纸面报告保留节目、时间和可点击链接；应用内回听链接只适用于仍可访问这台服务的读者，外部分享应附公开节目链接。

## CSS 与 PDF 预算先确定

网页沿用原应用：深色 zinc 背景、原紫色强调、原字体、细边线和卡片密度。小封面用于识别来源；每块标题直说内容，不出现新的英文品牌口号、巨大 01/02 编号、反问句和笼统的“核心洞察”。每块文字使用明确的解释／原话／上下文／资料关系，少写“主轴”“赋能”“生态”“落地路径”等抽象判断。

纸面使用独立打印样式：A4 210×297mm，四边十二毫米边距；可用区域约 186×273mm；两列各九十毫米，间距六毫米。标题约十八磅，块标题十一点五磅，正文十至十点五磅，来源八点五磅。白底深字，紫色只用于标题和小标签。

单页报告用固定内容预算；双页报告明确设置第二页，而不是任由长文流到第三页。应用侧栏、播放器、交互按钮不进入报告。卡片禁止跨页，内容过量时减选或切换双页，不截掉引用、不无限缩字号。上述数量是设计起点，正式选版后用中文、英文和长标题真实数据渲染验证页数。

报告的 HTML/CSS 固定，由程序填入结构化内容；模型不自由生成 CSS、网页结构或长篇 Markdown。网页可以展开更多内容，PDF 只导出预览中明确选中的块。每个链接和来源归属于同一份已保存报告，导出不再重新生成内容。

## 背景检索：围绕具体节目和实体

先从文稿取得嘉宾姓名、文章／书名、术语或历史事件，再按这些实体查询。优先节目官网、作者个人网站、出版社、论文原站和官方文档。介绍约六十至一百字，附网页来源和查询时间。

截至 2026-10-01，[DeepSeek 官方 Claude Code 接入文档](https://api-docs.deepseek.com/zh-cn/quick_start/agent_integrations/claude_code/) 明确支持原生 Web Search。其 [官方搜索实现](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/web/web-search-deepseek/src/provider.ts) 通过 Anthropic Messages 路径发送 web_search 工具并读取搜索结果和引用。这是可评估的集成路径，搜索还会产生额外模型 Token 费用。

当前项目经第三方 aiping.cn 的 OpenAI-compatible 接口调用 DeepSeek 模型，没有证据说明该接口透传官方原生搜索；现有 LLMClient 也没有保留搜索工具结果的处理。现有 Tavily 路径可作为另一种接入选择，但当前无启用的搜索凭证。本轮只核实官方能力，不更改配置或试调用新收费接口。

背景检索可以与摘要模型分开接入，不需要为了搜索重做全文分析。只有确实取得的网页结果和读到的内容才用于补充；模型记忆不能冒充搜索。节目的说法、节目提到的资料、搜索补的介绍和延伸阅读保持明确标签。

## 提示词与 API 的后续设计顺序

先选报告编排并定每块件数、长度、来源栏和 PDF 页面预算，再定结构化字段，最后写提取与补充提示词。

共同字段：episode_id、节目名称、单集标题、说话人、原文引句、字幕起止时间、内容类型。概念另有原词与白话解释；金句另有上下文与明确标注的译文；资料另有标题、类型、关系与验证链接；背景另有网页来源、查询时间及简介。

流程：取得全文 → 分段抽取这些具体内容块 → 原句与时间匹配 → 合并重复概念、保留各期出处 → 按需要搜索具体实体 → 按件数与长度精选 → 固定 CSS 渲染 → 校验一／两页并导出。

本轮推荐默认“本期速览”，以“逐期摘录”作为查看全部节目内容的入口。新词、金句、资料既能单独导出，也能通过关注项调整综合报告。五方案共用相同应用外壳和内容证据，各自调整内容比重与纸面编排。

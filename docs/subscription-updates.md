# 订阅源更新

## 节奏统一在设置里调

所有更新间隔都在 **设置 → 应用 → 订阅更新** 里管理，存数据库，改完立即生效，不需要重启后端，也不再读环境变量。

| 参数 | 默认 | 说明 |
|---|---|---|
| 订阅更新间隔 | 12 小时 | YouTube 与 RSS 共用同一个间隔 |
| 巡检频率 | 15 分钟 | 后台多久看一次有没有到期源 |
| 每轮刷新源数 | 1 个 | 一次巡检只处理一个源，避免同时打多个平台 |
| 字幕抓取间隔 | 2 分钟 | 每期字幕之间等多久，防限流 |
| 存量字幕补捞间隔 | 60 分钟 | 多久找一批缺字幕的历史节目 |
| 每批补捞期数 | 8 期 | 每次最多投递多少期 |

## 后台静默刷新

定时刷新不写任务记录：任务面板的「进行中」只显示你自己触发的操作，历史里也不会被十几分钟一次的自动刷新淹掉。刷新进度只留在内存里，「历史」页顶部用一张卡片汇总当天的自动更新情况——「已完成 x/y 更新」，失败的源会在下一轮重试。

同一个源在任意时刻只有一次刷新在跑：定时、手动、详情页自动触发都用 `refresh:<feed_id>` 去重，共享同一个任务。

## YouTube：先展示视频，再补文稿

1. 新订阅或刷新时，`FeedSyncService` 先获取最近 15 个上传视频。
2. 优先使用官方 RSS。RSS 请求失败或返回非 RSS 页面时，使用 yt-dlp 的上传播放列表，只取列表，不逐个解析视频。
3. 立即保存标题、发布时间、封面等列表信息，更新订阅的节目数量，完成 `refresh` 任务。
4. 缺元数据或缺文稿的剧集进全局字幕队列：单通道、按「字幕抓取间隔」节流，新剧集插到队首，历史积压排在后面慢慢消化。时长、真实发布日期、简介和封面在队列里逐期补齐，已有文稿直接复用。
5. 字幕不可用只记录该期的原因，不隐藏视频，也不把成功的列表同步标成失败。被 429 限流时该期留在队首，并把下次抓取窗口拉长到 3 倍。

队列状态在任务面板的「进行中」里可见（排队位置与预计时间），间隔在同一个设置页调节。

官方 RSS 的日期是精确日期；备用上传列表提供的相对日期由 yt-dlp 估算。两种入口均只获取最近 15 期，不代表完整历史归档。

## B 站：暂停自动更新

定时检查和新订阅后的自动节目同步均暂停。保留已有订阅、节目、文稿和手动刷新入口，不修改用户的收藏或阅读状态。详情页会显示自动更新暂停的提示。

## RSS

与 YouTube 共用同一个更新间隔，解析后只插入新剧集，已有剧集的标题/简介修订不会回灌。

以上同步只访问来源平台，不调用大模型，不自动执行本地音频转录。
